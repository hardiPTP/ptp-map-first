# Accessibility: WCAG 2.2 AA audit

Audit date: 2026-10-23. Scope: the home screen (map, top bar, chips, bottom sheet, feed, notices), map markers, tags, popups and pin text, search, account / area / claim sheets, the create flow (placing + details), the detail view and its comments, and /kitchen-sink.

How it was checked:
- Code review of every component against the criteria below.
- Contrast computed from the values in `src/design/tokens.css` (WCAG relative luminance; alpha tokens composited over their background). This is now a unit test (`tests/unit/a11y.test.tsx`, "token contrast pairs").
- axe-core 4.10 (new devDependency, no runtime dependency): in jsdom unit tests (Google mocked; colour-contrast rule off because jsdom has no layout) and in Chromium (Playwright) with all `wcag2a/2aa/21a/21aa/22aa` rules, including colour contrast.
- Browser runs: /kitchen-sink at 320 px, with and without the WCAG 1.4.12 text-spacing override; the home page 3 times (the Maps Demo Key cap allows few): Tab order, dialogs, combobox, sheet keys, 320 px reflow, reduced motion, placing flow. Screenshots were looked at.

Results after the fixes: axe on /kitchen-sink: 0 violations. axe on the home page: 1 (`target-size`, overlapping map markers, see Remaining). `npm run typecheck` and `npm run lint` clean; `npx vitest run`: 16 files, 228 tests pass (203 before + 25 new).

## What was checked, by criterion

- **1.1.1 Non-text content.** Icons are `aria-hidden` (Icon primitive) with text beside them or a labelled button. Markers: glyph type was not spoken; fixed. "You are here" marker had no text; fixed. Card verified mark had no text; fixed. Detail photo has `alt=""` (not my file; proposal below).
- **1.3.1 Info and relationships.** No `h1`; fixed. Sheet h2, card h3, dialog h2 / h3: fine. Feed and notices are lists. Chips are toggle buttons in a labelled group; create-flow chips and tiles are radios in radiogroups. Kitchen sink put toggle chips in a `radiogroup`; fixed. Search results had a `listbox` whose options could not be reached; rebuilt as a combobox. The sheet is now a labelled region ("Pulse").
- **1.3.2 / 2.4.3 Meaningful sequence, focus order.** The DOM order was map (every marker, then every tag and popup) before the top bar, so Tab went through about 60 map stops before search. Fixed: top bar, map buttons, list, then the map. Each pin was 2 or 3 Tab stops (marker, pin text, tag); fixed (the duplicates are pointer-only). Focus was lost when "N more notices", "Pay and claim" or "+ Pin" went away; fixed.
- **1.3.4 Orientation.** Not locked. Pass.
- **1.3.5 Input purpose.** "Your name" used `autocomplete="off"`; now `nickname`.
- **1.4.1 Use of colour.** Pin types use shape + glyph as well as colour; selected chip changes fill and `aria-pressed`. Pass.
- **1.4.3 / 1.4.11 Contrast.** See the table.
- **1.4.4 / 1.4.10 Resize, reflow.** Viewport allows zoom (no `user-scalable=no`). At 320 px: no horizontal page scroll (kitchen sink and home), the chip row scrolls on its own (allowed), card text wraps or clamps to 2 lines with the full text in the detail.
- **1.4.12 Text spacing.** Override applied on /kitchen-sink: nothing clipped; single-line pills (chips, tags, buttons) keep their text because they are sized by line-height and nowrap.
- **1.4.13 Content on hover or focus.** None.
- **2.1.1 / 2.1.2 Keyboard, no trap.** All controls are native buttons, links and inputs. Sheet handle: Enter / Space cycle and (new) Arrow Up / Down step. Google's map div takes focus and pans with the arrow keys, +/- zoom. Top sheets now trap Tab and close on Escape. Detail view: Tab leaves the dialog (proposal below).
- **2.2.1 / 2.2.2 Timing, moving content.** Snack hides after 3.5 s (a confirmation; the posted card stays at the top of the list). The marker pulse loops forever (Remaining).
- **2.3.3 / reduced motion.** `prefers-reduced-motion: reduce` turns off the pulse (verified in Chromium: `animation-name: none`), the create sheet rise and every transition (base.css). Pass.
- **2.4.1 Bypass blocks.** With the new order the list is 12 Tab stops in, no skip link needed.
- **2.4.2 Page titled / 3.1.1 Language.** `<title>Push The Pin</title>`, `lang="en-IN"`. Pass.
- **2.4.7 Focus visible.** Every control has the orange ring or the default ink outline. Search options (focus stays in the field) now show the ring on the arrow-key choice.
- **2.4.11 Focus not obscured.** A focused card in the list at peek height was inside a 0 px scroll area; now the list rises to half. A focused marker under the top bar or the sheet now flies into the visible band (keyboard focus only, `:focus-visible`).
- **2.5.3 Label in name.** OK, except "@ Hill Road" whose name is "Everything at Hill Road" (Remaining, low).
- **2.5.7 Dragging movements.** Sheet: tap / Enter cycles, Map / List pill. Map pan: double-tap zooms in about the tapped point and "−" zooms out (so moving the view needs no drag), plus search, cards and clusters fly the map. Placing a pin needed a drag; now a tap on the map moves the spot there.
- **2.5.8 Target size.** Markers, tags, pin text 44 px through `::after`; chips 44 tall; shell buttons 44 / 46; place dots 38. The popup "@ Place" link was 16 px tall right above another target; now 24 px. Overlapping markers remain.
- **3.3.1 / 3.3.2 Labels, errors.** Fields have labels or `aria-label`; claim and create errors use `role="alert"`; the comment counter is tied to the field with `aria-describedby`.
- **4.1.2 Name, role, value.** Markers had `aria-pressed` while opening a dialog; now `aria-haspopup="dialog"`. Sheets were `aria-label`led dialogs with no focus handling; now modal (useModal). Search is a WAI-ARIA combobox.
- **4.1.3 Status messages.** "Pinned...", "Thanks. It shows here once it has been checked.", "That did not send", the area "Location is off" note were live regions mounted together with their text (often not read). Now the regions are always rendered. New: search result count, the placing "Spot: <place>", the sheet count line (`aria-live="polite"`).
